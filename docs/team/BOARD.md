## 1. 고사양 PC
| 순서 | 먼저 필요한 것 | 내가 할 일 | 다음으로 넘기는 것 |
|---|---|---|---|
| H-1 | 현재 원본과 저장소 접근 | 최신 코드와 빌드 상태 확인 G0 | H-2에서 사용할 검증 기준 코드 |
| H-2 | G0 확인 | 공통 데이터 형식·시험 입력·작업 Issue 준비 G1 | L1/L2에게 준비 완료와 시작 기준 |
| H-3 | G1 준비 | 공통 시험 입력으로 지도·별·안내 화면 R0, 실제 차량 지원 P1 조사 | 내비/별 모듈을 받을 화면과 검증 환경 |
| H-4 | L1의 N1 코드·예시·테스트 | 검토 후 지도·표식·주행 안내 연결 I1 | L1에 연결 성공 또는 구체 수정 요청 |
| H-5 | L2의 S1/S2 코드·예시·테스트 | 검토 후 방위 별·정차 액자·기록 저장 연결 I2 | L2에 연결 결과/저장 시험/수정 요청 |
| H-6 | N2/S2 보강 결과, 실제 센서 지원표 | 검증된 실제 입력 연결, 전체 주행 흐름 시험 V1 | 각 노트북에 담당 오류와 재시험 조건 |
| H-7 | 합의한 기획 범위 | 시작·성단·여행 리캡 등 남은 기능을 배분·화면 연결 | L1/L2에 구체 추가 작업과 공통 변경 |
| H-8 | 기능 수정·보강 재전달 | 전체 회귀시험, 코드·앱·실행 안내 정리 REL | 사용자와 팀원에게 최종 검증 결과 |

[추정] L1 결과를 기다릴 때 L2/시험 화면/차량 지원 확인을 진행한다. HIGH 한 장비에서 화면·센서·통합을 동시에 서로 다른 AI가 수정하지 않는다.

## 4. 진행 확인은 누가 작성하나?
[추정] **각 담당 AI가 작성한다.** 보내는 AI는 코드·테스트·다음 행동을 PR/Issue에 적고, 받는 AI는 내용을 읽어 적용·검증하고 회신한다. 사람이 별도 인수인계 대기열을 채우는 절차는 없다.
[추정] 사람이 자기 AI에 “공통 안내와 내 담당 작업을 읽고 다음 단계 진행해”라고 요청하면 AI가 실제 기록을 확인하고 이어간다. 실행하지 않은 AI가 자동 감시하고 처리한다고 가정하지 않는다.
[확실] 이 문서에는 실제 개발 완료 상태를 미리 체크하지 않았다. 실제 완료는 코드·시험·통합 기록으로 확인한다. 승인 코드 버전의 기술 기록은 [BASELINE](BASELINE.md)을 HIGH AI가 관리한다.
