# StarLog 별자리 멜로디 구현 분석과 작업 순서

기준일: 2026-11-14 · 기준 프롬프트: `misic code prompt.md`

## 분석 결과

- 앱은 Kotlin/Android(minSdk 34)이며 화면은 XML/Compose가 아니라 Activity와 Canvas/WebView를 코드로 구성한다.
- 주행 기억은 `Visit → MemoryStar → Constellation/ConstellationMember`로 저장된다. 멜로디 입력에 필요한 별 ID와 연결 순서는 이미 보존되지만 별도의 화면 좌표는 없으므로 위·경도를 중심점 기준 로컬 미터 좌표로 투영한다.
- SQLite 저장소에는 비파괴 v1→v2 마이그레이션, LIVE/REPLAY 분리, 외래키가 구현돼 있다. 기본 멜로디는 같은 패턴으로 v3 테이블을 추가하는 것이 가장 안전하다.
- 현재 음악 라이브러리나 외부 음악 생성 SDK/API 자격 정보는 없다. 기본 멜로디 재생은 오프라인 PCM으로 구현하고, 외부 서비스에는 공급자 중립 요청 데이터만 만든다.
- UI 기준은 제공된 `IVI_2_3_03_여정종료_오르골악보_1700x1184.png`와 대응 SVG/HTML이다. 검정 배경, 금색 강조, 얇은 오선과 별 연결선, muted label을 Android Canvas에 반영한다.

## 구현 규칙

- 회전은 매번 원본 좌표에서 계산하며 회전된 좌표를 다음 계산의 입력으로 쓰지 않는다.
- 화면 좌표의 작은 Y가 높은 음이다. 기본 C Major를 포함해 사용자가 선택한 장음계로 C3–C7에 우선 매핑한 뒤 C4–C6 선호 음역으로 옥타브만 보정한다.
- 화음 후보는 정규화된 회전 Y로 판단하며 그룹의 최솟값과 최댓값이 임계값 이내인 경우만 묶는다.
- 연주 순서는 `connectionOrder`이며 X좌표로 재정렬하지 않는다. 화음 구성원은 최초 구성원 시점에 같이 시작하되 원본 순서를 각 음표에 유지한다.
- 유사도는 음정 40%, 상대 음높이 25%, 리듬 20%, 화음 15%이고 평균이 아니라 기존 악보 중 최댓값을 쓴다.
- 확정 악보가 있으면 다른 ID로 덮어쓰지 않는다. 명시적 재생성/교체 기능을 만들기 전까지 원본을 보존한다.
- 실제 외부 생성 호출을 하지 않은 상태는 UI와 보고서에서 “편곡 입력 준비”로만 표현한다.

## 검증 상태와 제한

- Android 독립 코어 파일은 Kotlin/JVM 컴파일 및 실행 스모크 검증을 통과했다. 후보 80개를 평가하고 동일 입력에서 같은 각도와 ID가 생성됐으며 조성 변경 시 별도 ID가 생성된다.
- 전체 Gradle 테스트는 현재 PC에 Android SDK 경로가 없어 구성 단계에서 중단된다. SDK가 준비된 환경에서 `:app:testDebugUnitTest`, `:app:lintDebug`, `:app:assembleDebug`를 다시 실행해야 한다.
- 실제 Suno/외부 음악 생성, 편곡 오디오 저장, 차량/에뮬레이터 화면 검증은 완료로 간주하지 않는다.
